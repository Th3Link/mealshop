# Native recipe interaction contract

The customer overrides the older concept's collapsed secondary parts: every part remains open.
Use the approved compact row proportions and two-column composition, retaining Nextcloud controls,
colors/fonts and visible section/column labels. Individual row labels remain available to assistive
technology without repeating visible “Choose ingredient”. Exact conversion evidence stays visible
when a non-mass unit requires it. Optional added fields remain visible once present.

A plus action per ingredient opens native actions for temperature or homemade preparation. No
water-only shortcut, dietary inference or preset bread phases. Existing temperatures display inline;
remove uses a labelled icon. Parts own their ingredient/step lists, with compact preparation timing,
visible associations and a clear title. On mobile the columns stack without horizontal overflow.

Homemade is an explicit recipe choice. Its preparation part requests actual input ingredients and
instructions; the finished reference is labelled and links to that part. Buying again confirms the
removal of a simple, unshared preparation. Shared/nested dependencies block destructive conversion
with an actionable explanation. Original declared output and source facts remain distinct from input
nutrition; no cooking loss or yield is inferred. Read mode mirrors the same open section hierarchy.

Apply UX-UI-Pro-Max for task flow, Taste for density/alignment and frontend engineering for accessible
controls and stable IDs. The native Nextcloud hierarchy overrides other palettes, fonts and kits.
